## 撤销发布订阅，改为显式直连（同日）

- 用户反馈 EventBus 阅读性不高，判断成立。上一轮把「内核→UI 的展示通知」（一对多、适合事件）和「内核内部状态同步」（一对一、应显式调用）混进同一条总线；还让 RunManager 订阅总线观察自己参与的事件、靠 `tool.completed` 推断状态恢复，订阅顺序成了隐含约束，IDE 无法从 emit 跳到接收方。
- 改法：删除 `src/app/event-bus.ts` 和 `EventSink`；事件回归一对一 `AppEventListener`（内核 emit → 入口 listener）；新增 `ApprovalStateReporter` 端口由 RunManager 实现，并作为 `ToolInvoker.invoke` 第三参随调用传 `this`，化解装配期循环依赖。ToolService 用 `reporter.approvalRequested()` + `.finally(reporter.approvalSettled())` 显式回报，状态恢复不再依赖 Agent 发出工具完成事件（拒绝/取消/抛错都会恢复）。
- 保留：ports 上移、createApp 装配根、ToolInvoker 端口、AgentRegistry 接线、Ajv 缓存、双 UUID 修复。
- 验证：pnpm check → typecheck 通过、15/15 测试通过；CLI 端到端允许路径正常；全仓无 EventBus/EventSink/publish 残留。
- 结论：发布订阅适合阶段 3 Electron 的 Main→多 Renderer 广播或阶段 5 事件持久化/重放；当前一对一且需改内部状态的场景不值得付间接性成本。

## 按「直线循环」重写阶段 1（同日第五轮，最重要）

- 用户连续质疑：① cancel 不优雅；② 真实 API agent 里自定义 tool 与 print 是脱钩的，我们反而耦合；③ 本质上就是模型注入 / prompt 注入 / 工具注入，只多一层 agent 注册。判断全部成立，前几轮的「分层语义」在这个规模下属于提前为阶段 3 付成本。
- 诊断的四处耦合：ToolService 构造注入 `emit` 并在 invoke 里发 `approval.requested`；create-app 把 onEvent 同时注入 ToolService/RunManager；CLI 审批网关自己打印参数而 print 里用空 case + 注释避免重复打印；AppEvent 把数据面与控制面混进一个联合类型。根因是把 Electron 的 Main→Renderer 广播提前搬进阶段 1（撤 EventBus 时只砍了订阅表，没砍注入）。
- 最终形态：`src/` 6 文件 + `tests/` 3 文件，共 618 行（此前 1111 行）。注入集中在 `cli.ts` 调用 `runTask({ input, agent, systemPrompt, tools, workspace, approve, print })` 一处。
  - `contracts.ts`：纯类型（ToolDefinition / ChatMessage / ModelReply / Agent / RunOptions / RunResult / ApprovalDecision）。
  - `agents.ts`：`Map<string, Agent>` + Mock（按 messages 推导下一步，最后 done）。这是相比直接调 LLM API 多出的唯一一层。
  - `tools.ts`：工具清单 + `validateInput`（Ajv 按 name 缓存）；工具 `run()` 只返回 ToolResult，不认识 UI。
  - `run.ts`：唯一直线循环——取下一步 → 判断 message/tool_call → 校验 → 权限分支 → 执行 → 打印 → 结果回灌。审批是分支，取消是 `break`。
  - `cli.ts`：`approve` 展示真实参数并返回 allow/deny/cancel，`print` 是唯一出口。
- 删掉：AppEvent / AppEventListener、emit 注入、装配根与 AppHandle、let cancelImpl 惰性接线、ApprovalStateReporter/RunControl、ToolInvoker 端口、双 Registry、RunManager 类、AgentSession/AgentBridge/subscribe/dispose、waiting_approval 状态、AbortController（阶段 1 无工具读取 signal，属死抽象）。上一轮的 cancel 重构被这个形态直接吸收。
